# LEGO Tank Remote Control Project — 宏梦·初号机

一个以 ESP32 / ESP32-CAM 为硬件边缘节点、以 Python 为上位机控制层的遥控坦克与实时观测工程。项目包含完整的硬件电路设计、3D 打印结构件、LEGO 车身拼搭方案、控制固件和上位机控制软件。

![效果图](./lego/render/legotank.png)

> 宏梦·初号机是一台基于乐高 Technic 框架的履带遥控车，通过 WiFi + MQTT 实现远程操控与实时图传。

## 1. 项目概览

该仓库提供以下能力：

- 由控制软件在本地展示摄像头视频与 HUD 叠加信息。
- 通过 MQTT 接收控制板遥测包与监控板遥测包。
- 将控制板和摄像头监控板的信号强度、状态字段、统一进入 overlay 页面。
- 支持手动按键控制、蓝牙/键盘远程控制输入与视频流浏览器观测。
- 通过本地 HTTP 服务向浏览器或 OBS 端源提供稳定的 overlay 页面与 telemetry 接口。
- 提供完整的乐高拼搭说明书以及工程文件，便于复刻
- 提供完整的 3D 打印件设计（换挡器、摄像头固定座等）。
- 提供可直接在嘉立创下单的 PCB 电路板设计文件（含 Gerber、BOM、钢网）。

## 2. 系统架构

该工程可理解为三层：

1. **边缘硬件层**：ESP32 控制板 + ESP32-CAM 监控板固件。
2. **协议与数据层**：MQTT 主题、JSON payload 与 telemetry 语义。
3. **控制与展示层**：PyQt6 QWebEngine HUD / HTTP 页面 / Python 控制循环。

## 4. 硬件组成

### 4.1 控制板 (ESP32)

| 组件 | 说明 |
|------|------|
| 主控 | ESP32 双核 240MHz |
| 电机驱动 | TB6612FNG 双路 H 桥 |
| 舵机 | M1 换挡舵机 (0-180°)、M2 大灯 (PWM)、M3 逗猫棒 (PWM) |
| 电源 | 3S LiPo (11.1V) 电池，含分压电压检测 |
| 通信 | WiFi 2.4GHz + MQTT |

### 4.2 监控板 (ESP32-CAM)

| 组件 | 说明 |
|------|------|
| 主控 | ESP32-CAM (AI-Thinker) |
| 摄像头 | OV2640 200万像素，最高 1600×1200 |
| 视频流 | MJPEG over HTTP |
| 通信 | WiFi 2.4GHz + MQTT |

### 4.3 结构件

- **防滚架**：F1 赛车级安全理念，翻滚时保护内部组件不接触地面。
- **换挡器**：两档机械变速，通过 M1 舵机切换高低档位。
> PS：其实低速档已经够快了，换挡结构比较复杂，可以使用手动挡+用绳子把挡位固定在低速（后面）
- **摄像头固定座**：安装在车体前部，提供第一视角。
- 所有结构件均为 3D 打印件，FreeCAD 源文件可供修改。

### 4.4 PCB 电路板

PCB 使用嘉立创 EDA 设计，仓库提供：
- Gerber 文件（可直接下单生产）
- BOM 器件列表（可在立创商城直接购买）
- 钢网文件（可以选择开钢网，这样焊接会方便很多，毕竟全是 0603 的贴片元件）
- 器件位置文件（用于 SMT 贴片）

## 5. MQTT 通信协议

本仓库中的 MQTT 通信与 JSON 字段的完整规范请见 [MQTT_MESSAGE_FORMAT.md](MQTT_MESSAGE_FORMAT.md)。

### 5.1 主题结构

| 主题 | 方向 | 说明 |
|------|------|------|
| `tank/cmd` | PC → ESP32 | 控制指令 |
| `tank/telemetry/control` | ESP32 → PC | 控制板遥测数据 |
| `tank/telemetry/monitor` | ESP32-CAM → PC | 监控板遥测数据 |
| `tank/cmd/camera` | PC → ESP32-CAM | 摄像头参数配置 |

### 5.2 控制指令字段

| 字段 | 类型 | 取值范围 | 说明 |
|------|------|----------|------|
| `L` | 整数 | -255~255 | 左电机 PWM 占空比 |
| `R` | 整数 | -255~255 | 右电机 PWM 占空比 |
| `M1` | 整数 | 0~180 | 换挡舵机角度 |
| `M2` | 整数 | 0~255 | 大灯电平值 |
| `M3` | 整数 | 0~255 | 逗猫棒电平值 |

### 5.3 安全机制

- **指令超时保护 (Watchdog)**：若 500ms 内未收到任何 `tank/cmd` 消息，ESP32 自动停车。
- **电机换向保护**：（硬编码在控制板中，上位机发送指令时也会遵守）检测到方向切换时先强制输出 0 一段时间，保护驱动电路。

## 6. 配置说明

### 6.1 控制软件配置

控制软件使用 [control_software/config.yaml](control_software/config.yaml) 作为默认预设配置文件。配置文件不存在时会自动生成默认配置文件。

该文件包含：

- **MQTT 连接**：broker 地址、端口、订阅主题。
- **视频流**：stream_url、分辨率、画质、帧率。
- **控制参数**：按键绑定、功率上限、加速率、制动强度、转向因子。
- **换挡参数**：高低档位阈值、换挡时间、M1 舵机角度。
- **伺服电机**：数量、名称、段数、idle 电平、各段按键/电平/过渡时间/触发方式。
- **视频处理**：翻转、旋转、自动画质调节。

控制软件在启动时会优先从同目录下的 YAML 文件读取参数，并在代码里用 `DEFAULT_CONFIG` 作为代码级默认兜底。

### 6.2 控制板固件配置

控制板配置见 [legotank_esp32/config.h](legotank_esp32/config.h)，包含：

- 引脚定义（电机、舵机、电池检测）
- PWM 参数（频率、分辨率）
- 电池分压电阻值
- WiFi / MQTT 连接参数
- 运行时参数（遥测间隔、看门狗超时、换向保护时间）

## 7. 伺服电机控制

控制软件通过"伺服电机"设置页提供灵活的伺服电机分段控制：

- **数量**：可配置 1~8 个伺服电机（默认 2 个），M1 留给换挡舵机专用。
- **段数**：每个伺服电机可独立配置 1~8 段，动态增减段数后界面自动重建。
- **电平值**：使用 0~255 电平值而非角度，M2/M3 引脚直接输出 PWM（频率 1200Hz，分辨率 8bit），消除 LED 频闪。
- **不触发电平**：每个伺服电机有独立的 idle 电平值。
- **触发方式**：每段支持"按住触发"（按下生效，释放回 idle）和"按键切换"（按一次切换，再按一次回 idle）两种模式。
- **平滑过渡**：每段可配置独立的过渡时间，伺服电机会在设定时间内平滑过渡到目标电平。

按键行为逻辑：
- **按键切换**：当前为该段 → 回到不触发；当前不是该段 → 切换到该段。
- **按住触发**：按住 → 切到该段；释放 → 回到不触发。
- 在任意一段按下另一段的按键，就切换到那一段。

## 8. 运行步骤

### 8.1 环境准备

1. 安装 Python 依赖：

   ```bash
   pip install -r requirements.txt
   ```

2. 确保 MQTT Broker（如 Mosquitto）在局域网内正常运行。

3. 将 ESP32 控制板和 ESP32-CAM 监控板固件分别烧录到对应硬件。

### 8.2 启动控制软件

```bash
python control_software/infinite_rc_controller.py
```

### 8.3 测试工具

- **遥测监控**：`python test_tools/telemetry_monitor.py` — TUI 界面实时查看控制板和监控板遥测数据。
- **连通性测试**：`python test_tools/test_mqtt_server.py` — 验证 MQTT Broker 是否正常工作。
- **一键调试**：`python test_tools/debug.py` — 同时启动控制软件和遥测监控。

### 8.4 快速 MQTT 测试

```bash
# 发送控制指令
mosquitto_pub -h 192.168.2.45 -t tank/cmd -m '{"L":200,"R":200}'

# 订阅遥测
mosquitto_sub -h 192.168.2.45 -t tank/telemetry/control
```

## 9. 安全说明

该项目当前的通信设计是：

- MQTT Broker 连接：默认基于 TCP / 1883 端口。
- MQTT 载荷：JSON 文本，未做协议层加密。
- 视频流：HTTP / 视频源地址，由本地网络环境提供。

因此，当前工程存在明显的安全限制：

- 消息在网络中没有 TLS / SSL / MQTT over TLS 的保护。
- 车体命令、遥测、RSSI、系统状态等都可能以明文形式经过网络。
- 设备接入环境应当控制在受信任的局域网，或后续增加 VPN / SSH 隧道 / MQTT TLS / 设备级认证后再投入真实生产场景。

## 10. 已知运行注意事项

- 该项目是物理硬件驱动型工程，强依赖网络与 MQTT Broker 可达性。
- 如果设备没有实时发布消息，控制软件会在界面中持续显示等待状态。
- `telemetry_monitor.py` 是排查 MQTT 输出字段与主题路由的辅助工具。
- 如果某个字段没有被摄像头监控板或控制板正常填充，窗口 HUD 也会出现"图层灰"/"缺字段"的显示现象。
- ESP32-CAM 监控板需设置静态 IP，确保视频流地址稳定。
